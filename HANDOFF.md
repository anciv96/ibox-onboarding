# Передача проекта — с чего начать

Этот файл — для тех, кто получил репозиторий на ревью и деплой. Короткий
путь по документации и по самому важному, что нужно знать перед тем, как
трогать код.

## Порядок чтения

1. **Этот файл** — что где лежит и что сделать в первую очередь.
2. **[README.md](README.md)** — инструкция для руководителя (не разработчика):
   как выдавать приглашения, проверять ответы стажёров. Полезно для
   понимания продукта.
3. **[CLAUDE.md](CLAUDE.md)** — техническая документация: архитектура,
   принятые решения и почему они такие, известные ловушки. Самый
   подробный и самый важный файл для ревью — там же вся история решений
   по проекту, а не только текущее состояние.
4. **[DEPLOY.md](DEPLOY.md)** — варианты деплоя: Render/Railway (готовый
   `render.yaml`/`Procfile`) или свой VPS через Docker (`docker-compose.yml`,
   рекомендуемый вариант, раздел «Вариант C»).

## Данных в этом репозитории нет — специально

`.gitignore` исключает все файлы БД (`db.sqlite3`, `db_public.sqlite3`),
`.env`, `.env.public`, `backups/`. В репозитории — только код и пустая
схема (миграции). Реальный контент курса (7 модулей, банк вопросов
финального теста и тренировки) и данные тестового стажёра передаются
**отдельно**, JSON-выгрузкой (`python manage.py dumpdata`), не через git —
там хэши паролей и данные живого человека, это не должно лежать в
репозитории, даже приватном.

Когда получите файл выгрузки:
```bash
python manage.py migrate
python manage.py loaddata <файл-выгрузки>.json
```
Дальше **обязательно** смените пароль импортированного админа
(`python manage.py changepassword admin`) — исходный пароль слабый, он был
временным для тестового сервера с ноутбука.

Если выгрузки нет или нужна база с нуля для разработки — `python manage.py
seed_demo_data` создаёт тестовые демо-данные (модули, ученики, пароли
известны, см. `CLAUDE.md`) — **не для прода**, только чтобы что-то увидеть
локально.

## Быстрый локальный запуск

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo_data
python manage.py test          # 113 тестов, должны проходить все
python manage.py runserver
```

## На что обратить внимание перед деплоем

- **CSS не через CDN.** Стили — заранее собранный `static/css/app.css`
  (закоммичен). Если правите классы в шаблонах — пересобрать: `cd tailwind
  && npm install && npm run build`. Иначе новые классы не подхватятся.
- **Postgres ≥ 15 обязателен в проде** (Django 6.1 этого требует; локально
  можно на SQLite). `dj-database-url` уже настроен, просто передать
  `DATABASE_URL`.
- **Docker-стек не проверен вживую** — собирал без доступа к Docker
  (среда без него), только по документации и логике `Dockerfile`. Первую
  сборку (`docker compose up -d --build`) стоит внимательно проверить.
- **Узбекский перевод** — весь UI и весь контент курса переведены, но
  переводчик — не носитель языка (Claude). Стоит дать на вычитку
  узбекоговорящему, если это боевой продукт, а не демо.
- **Финальный тест**: банк вопросов и случайная выборка (17
  закрытых + 3 открытых из большого банка) готовы. НЕ сделано: серверный
  таймер, жёсткий счётчик «одна попытка» (сейчас пересдача открывается
  только вручную через статус «на доработку» — это осознанное решение, не
  баг) и счётчик уходов со вкладки, видимый админу — если это ещё нужно,
  см. соответствующий раздел в `CLAUDE.md`.

## Вопросы по продукту

Все решения по логике (правила зачёта модуля, пересдачи, статусы ученика,
геймификация, контент) — на стороне заказчика (владелец этого репозитория
на GitHub). Технические договорённости и почему они такие — в `CLAUDE.md`,
но если что-то в бизнес-логике непонятно или кажется неправильным —
уточняйте у него, не переделывайте молча.
