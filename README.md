# Онбординг Sales Doctor — инструкция для руководителя

Это инструкция «как пользоваться» для тебя как админа. Если ты разработчик
и получил этот репозиторий на ревью/деплой — начни с [HANDOFF.md](HANDOFF.md)
(с чего начать, что почитать по порядку) и раздела «Установка для
разработчика» ниже. Техническая документация — в [CLAUDE.md](CLAUDE.md),
инструкция по деплою — в [DEPLOY.md](DEPLOY.md).

## Установка для разработчика

```bash
git clone <адрес этого репозитория>
cd ibox-onboarding
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo_data   # тестовые данные, не боевые
python manage.py test             # 113 тестов, должны пройти все
python manage.py runserver
```
Админка на локальном запуске: `http://127.0.0.1:8000/admin/` (`admin` /
`admin12345` — только для локальной тестовой базы). Реальные данные курса
в репозиторий не входят — передаются отдельно, см. [HANDOFF.md](HANDOFF.md).

Дальше — деплой на сервер, см. [DEPLOY.md](DEPLOY.md) (Docker на своём VPS
или Render/Railway).

## ⚠️ Важно: сначала задеплой

Ссылка вида `http://127.0.0.1:8000/...` работает **только на твоём
компьютере** — это локальный сервер для разработки. Стажёр её открыть
не сможет, даже если перешлёшь.

Чтобы выдавать реальные ссылки, сайт нужно один раз задеплоить — на
Render/Railway или на своём сервере через Docker, см. [DEPLOY.md](DEPLOY.md).
После этого у тебя будет постоянный адрес — дальше всё, что описано ниже,
работает через него.

Всё, что ниже, можно попробовать уже сейчас локально (раздел
«Как запустить у себя» в конце), чтобы освоиться перед деплоем.

---

## Пришёл новый стажёр — что делать

1. Зайди в админку: `https://<твой-домен>/admin/`
2. На главной нажми **«Пригласить стажёра»** (или в меню **«Приглашения»** →
   **«+»**).
3. Впиши имя стажёра (как в базе — под ним же он потом появится в
   списке учеников) и сохрани.
4. Нажми **«Скопировать ссылку»** (кнопка есть и в списке приглашений, и на
   странице приглашения) — в буфере будет полный адрес.
5. Отправь ссылку стажёру любым удобным способом (Telegram, WhatsApp,
   email). Больше ничего объяснять не нужно — на странице по ссылке он
   увидит своё имя, придумает логин и пароль и сразу попадёт в курс.

Ссылка именная и одноразовая: как только стажёр зарегистрируется, она
помечается «Использовано» и повторно не сработает — если он потеряет
доступ, просто выдай новый пароль через
**«Пользователи»** (сброс пароля) или создай новое приглашение под
другим именем.

## Как стажёр проходит курс

- Модули открываются по порядку — следующий станет доступен только
  после того, как он верно ответит на все контрольные вопросы
  текущего. Если ошибся — попытка логируется, и можно пройти сразу
  заново, ждать не нужно.
- В конце — финальный тест из трёх частей: вопросы с вариантами,
  открытые вопросы и кейсы с возражениями клиента.
- После отправки теста стажёр видит на своей странице «Тест отправлен,
  ждёт проверки» — дальше решение за тобой.

## Как проверить результаты и принять решение

Главная страница админки (`/admin/`) сразу показывает, что требует внимания:
сколько работ ждёт решения, кто сейчас учится и на каком модуле, сколько
приглашений ещё не использовано. Красный счётчик у пункта **«Ученики»** в
меню — это число работ на проверке.

1. В блоке **«Ждут проверки»** (или в меню **«Ученики»**) открой стажёра.
2. В карточке видно всё разом: все ответы финального теста (тип вопроса,
   полный текст, ✅/❌ у вопросов с вариантами), ниже — попытки по модулям
   (в том числе неудачные) и все попытки финала, если он пересдавал.
3. При желании впиши **«Итоговый балл»** и **«Заметку админа»** (видна только
   тебе) и нажми **«Сохранить»**.
4. Прими решение кнопками вверху карточки:
   - **Допустить** — стажёр увидит поздравление;
   - **На доработку** — стажёру откроется кнопка «Пройти тест заново», старая
     попытка сохранится рядом с новой;
   - **Отказ** — стажёр увидит нейтральное сообщение с просьбой уточнить
     детали у тебя лично.

⚠️ Кнопки решения меняют только статус. Балл и заметку они не сохраняют —
сначала «Сохранить», потом решение (если забыл, админка предупредит о
несохранённых правках).

Решение по нескольким людям сразу: в списке «Ученики» отметь галочками и
выбери действие («Статус → Допущен» и т.д.).

## Автосохранение ответов у стажёра

Ответы сохраняются сами, как только стажёр выбрал вариант или напечатал текст —
не только по кнопке «Проверить». Если он обновит страницу, закроет вкладку,
у него сядет телефон или он откроет курс с другого устройства, всё вернётся
на место (внизу формы видно «Сохранено 14:05»). При пропаже интернета ответы
временно лежат на устройстве и отправятся сами, когда связь появится. Ты в
админке видишь только отправленные попытки — черновики никак не влияют на
результаты, пока стажёр не нажал «Проверить ответы» или «Отправить на проверку».

## Логотип iBox

Положи файл в папку `static/` проекта — он появится в шапке сам, ничего менять в коде не нужно:

- `static/logo-white.png` — **лучший вариант**: белый или светлый логотип на прозрачном фоне
  (шапка сайта синяя, такой логотип на ней смотрится лучше всего);
- `static/logo.png` — обычный (цветной) логотип. Если белой версии нет, он покажется на
  белой плашке, чтобы не потеряться на синем фоне.

Названия должны быть точно такими, формат PNG (лучше с прозрачным фоном, высота от ~100 px:
в шапке он ужмётся до 32 px). Если логотип уже содержит надпись «iBox», слово рядом
скроется само; останется только «— онбординг». Без файла в шапке просто текст «iBox — онбординг».
Логотип из `logo.png` также показывается в шапке админки.

После добавления файла на публичной копии с ноутбука выполни `scripts/public.sh restart`
(на своём локальном запуске `runserver` перезапуск не нужен, достаточно обновить страницу).
На боевом сервере файл едет вместе с кодом; после обновления запусти `collectstatic`.

## Язык интерфейса и тёмная тема

- В шапке сайта у ученика переключатель **RU / UZ** и кнопка смены темы
  (светлая/тёмная; по умолчанию — как в системе). Выбор запоминается в
  браузере. Переключатель есть и на страницах входа/регистрации — стажёр может
  выбрать язык до того, как войдёт.
- Весь интерфейс уже переведён на узбекский (латиница). ⚠️ Перевод сделан
  автоматически — пусть его прочитает носитель языка, поправить можно в
  `locale/uz/LC_MESSAGES/django.po` (см. CLAUDE.md).
- **Контент курса** на узбекском заполняется отдельно и необязательно: в
  карточке модуля раскрой блок **«Узбекская версия»** (название, видео,
  конспект), у вопросов и вариантов ответа есть поля «(узб.)». Если поле пустое,
  ученик увидит русский текст — сайт не сломается на полузаполненном курсе.

## Как редактировать контент (без программиста)

Всё — через `/admin/`, обычные текстовые поля. Модуль состоит из двух частей:

**1. Шаги обучения** (что стажёр изучает и делает) — в карточке модуля, блок
«Шаги обучения». Добавляй шаги кнопкой «Добавить ещё»:
- **Видео** — вставь YouTube ID (unlisted-ссылка);
- **Материал (текст)** — конспект, «запомни главное» (можно `#` для заголовков и
  `-` для списков — это markdown);
- **Практическое задание** — что нужно сделать («позвони коллеге по скрипту»,
  «найди клиента в CRM»). Включи «Нужна заметка», если хочешь, чтобы стажёр
  коротко написал, что сделал и понял;
- **Ссылка / файл** — ссылка на презентацию, документ, таблицу.
Порядок шагов и вопросов задавать вручную не нужно: новый шаг встаёт в конец, а
порядок меняется перетаскиванием (значок «⋮⋮» слева от шага). У каждого шага есть «Обязательный»: пока обязательные шаги не отмечены, тест
модуля закрыт. Необязательные шаги («по желанию») на допуск не влияют.
Стажёр сам ставит галочку «Просмотрено / Прочитано / Выполнено». Что он отметил
и что написал в заметках, видно в его карточке (блок «Шаги обучения»).

**2. Проверка знаний** — контрольные вопросы модуля (тут же, ниже; варианты
ответа — по ссылке «Изменить»). Стажёр видит кнопку «Проверить знания», когда
выполнил обязательные шаги; тест открывается на отдельной странице.

Финальный тест — раздел **«Финальный тест» → «Вопросы финального теста»**.

Порядок модулей и вопросов — просто число в поле «Порядок».

## Тест с ноутбука по публичной ссылке (пока нет сервера)

Ноутбук временно работает сервером через туннель ngrok — ссылка открывается с
любого устройства, пока ноутбук включён, не спит и есть интернет.

```bash
scripts/public.sh start    # запустить и показать публичную ссылку
scripts/public.sh status   # работает ли, какая ссылка
scripts/public.sh stop     # остановить
```

- База отдельная (`db_public.sqlite3`), демо-учеников там нет. Логин и пароль
  админа — в файле `.public_admin_password` (создаётся при первом запуске).
- Ссылка бесплатного ngrok **меняется при каждом новом запуске туннеля** —
  ссылки-приглашения, уже отправленные стажёрам, перестанут открываться. Чтобы
  адрес был постоянным, возьми бесплатный статичный домен в панели ngrok и
  запускай так: `NGROK_URL=твой-домен.ngrok-free.app scripts/public.sh start`.
- Стажёр при первом заходе увидит предупреждение ngrok и нажмёт «Visit Site».
- Ноутбук не должен засыпать: держи его включённым, с открытой крышкой и лучше от
  розетки (скрипт запускает сайт под `caffeinate`, но это не спасает при закрытой
  крышке на батарее).
- Сайт открыт всему интернету, включая `/admin/` — пароль админа не светить.
- Настоящие данные учеников лежат на ноутбуке. Когда появится сервер, базу нужно
  будет перенести (попроси — подготовлю выгрузку).

## Как запустить у себя (для теста перед деплоем)

```bash
cd /Users/h/PycharmProjects/ibox-onboarding
source venv/bin/activate
python manage.py runserver
```

Дальше:
- Админка: http://127.0.0.1:8000/admin/ (логин `admin`, пароль
  `admin12345` — смени после первого входа, это тестовые данные)
- Ссылки-приглашения бери из **«Приглашения»** в этой же локальной
  админке — они будут вида `http://127.0.0.1:8000/invite/...` и
  откроются только в браузере на этом же компьютере.

Тестовые данные (3 демо-модуля, демо-финалка, демо-ученики) можно в
любой момент пересоздать с нуля:
```bash
python manage.py seed_demo_data --reset
```
